# 2030 MYEONGDONG — FUTURE EMERGENCY PATH

긴급 통행 확보 장치 단독 제품 웹사이트 (스크롤 인터랙티브 3D)

## 폴더 구조 (제작 가이드의 `PRODUCT01/` 규칙)

```
PRODUCT01/
├── index.html                         ← 진입 파일 (이름 변경 금지)
├── README.md
└── assets/
    ├── css/style.css
    ├── js/
    │   ├── main.js                    ← 로딩 · 렌더 루프 · 스크롤 연결
    │   ├── timeline.js                ← 전체 스크롤 연출 (장면 순서/타이밍)
    │   ├── device.js                  ← 제품 GLB 부품 애니메이션
    │   ├── intro/                     ← V3 인트로 (파일 B의 IntroVortex.js · FlowStreams.js 재사용)
    │   │   ├── IntroVortex.js · FlowStreams.js  ← 파일 B 원본 그대로 (import 경로 2줄만 변경)
    │   │   ├── compat.js              ← 파일 B의 QUALITY·rng 대체 (원본 settings.js 값과 동일)
    │   │   └── IntroWorlds.js         ← 파일 B main.js의 카메라·패럴랙스 부분만 옮긴 연결 코드
    │   ├── worlds/lights.js           ← CONCEPT 배경의 절제된 빛줄기
    │   ├── worlds/city.js             ← 2030 명동 도시
    │   ├── worlds/cityCyber.js        ← V3 사이버펑크 레이어 (고층 타워·엣지 네온·전선·빛 번짐·헤이즈)
    │   ├── worlds/studio.js           ← 제품 스튜디오 (SOLUTION·REVEAL·VIEWER)
    │   ├── people.js · ambulance.js · ground.js · post.js · env.js · textures.js
    │   └── vendor/                    ← three.js r170, GSAP 3.12.5 (CDN 없이 동작)
    ├── models/
    │   ├── emergency-path-device.glb  ← 사이트가 실제로 불러오는 모델
    │   └── source/                    ← 원본 GLB (닫힌/열린 상태, 참고용)
    ├── images/                        ← 제품 렌더링 2장

    ├── videos/  audio/                ← 비어 있음 (선택 사용)
```

모든 경로는 상대 경로라서 상위 폴더(`TEAM01/` 등) 안에 그대로 넣어도 동작합니다.

## 실행 방법

- **`index.html` 더블클릭** → 바로 열립니다. (이때만 모델·폰트 내장 파일 `assets/js/offline-data.js`를 함께 불러오므로 첫 로딩이 조금 더 걸립니다.)
- VS Code "Live Server" 또는 **GitHub Pages**에서도 그대로 동작합니다.

### 코드를 고친 경우 (선택)

브라우저는 `assets/js/app.bundle.js` 하나만 읽습니다. `assets/js/` 안의 원본 파일을 고쳤다면 아래 명령으로 다시 묶어야 반영됩니다.

```
cd assets/js
npx esbuild main.js --bundle --format=iife --alias:three=./vendor/three/three.module.js --alias:three/addons=./vendor/three/addons --outfile=app.bundle.js
```

조 페이지·프로젝트 페이지 위치가 다르면 `index.html`의 `hud-nav` 부분 경로만 고치면 됩니다.

## 제품 모델에 대하여

- 원본 두 GLB(닫힌/열린)를 비교 분석해서 **부품별 실제 움직임을 계산**했습니다.
  - 중앙 패널 2장 → 힌지 축을 중심으로 정확히 90° 회전해 기둥이 됨
  - 양끝 경고 모듈 → 본체 약 7.9 mm, LED 링·상판 약 16 mm 단계적으로 상승 (원본 단위 기준)
  - 투명 아크릴 바 → 열린 모델에만 있으므로, 베이스 안에서 위로 올라오도록 구성
- 형상은 원본 열린 모델의 메시를 **그대로** 사용했고, 부품 이름·피벗만 다시 정리했습니다.
- 계산된 닫힌 상태는 원본 닫힌 GLB와 외곽 치수가 일치하는 것을 확인했습니다.

## 성능

- 화면 해상도는 프레임 속도에 맞춰 자동 조절됩니다.
- 모바일에서는 인원 수·텍스처 해상도·반사 해상도를 낮춥니다.
- 가장 무거운 장면은 도시(반사 + 군중)입니다. 노트북은 전원 연결 상태를 권장합니다.

## V3 변경 사항

- **INTRO** — 파일 B(10주차)의 실제 인트로 코드를 가져왔습니다. `2030 MYEONGDONG` 타이틀과 보라 빛 소용돌이(IntroVortex) → 스크롤 → PHASE 01·02 문구 → 보라 빛줄기(FlowStreams) 위에 `THE CITY RESPONDS BEFORE YOU DO.` → 짧은 페이드 후 어두운 명동 거리 위로 PROBLEM 문구.
  - 렌더러는 하나(이 사이트의 WebGLRenderer)만 사용하고, 파일 B의 장면은 같은 렌더러·같은 GSAP 마스터 타임라인 안에서 그려집니다.
  - 파일 B의 LightTrails(두 번째 WebGL 렌더러를 만드는 빛 줄 오버레이)와 RadialBlur(인트로 후반 흡입 구간 전용)는 가져오지 않았습니다.
- **명동 도시** — 거리 뒤로 고층 타워(셋백·커튼월 유리·금속 패널·핀·옥상 설비·안테나), 건물 모서리 시안 엣지 네온, 마젠타/바이올렛 크라운, 대형 세로 한글 간판, 파사드 빛 번짐, 거리를 가로지르는 전선과 전구 줄, 깊이 헤이즈, 짙은 남색 안개, 세로로 길게 번지는 젖은 바닥 반사.
- **PRODUCT REVEAL** — HOW IT WORKS 구간에서 제품은 왼쪽, 설명은 오른쪽 열. 좁은 화면에서는 제품 위 / 설명 아래로 쌓입니다.
- **INTERACTIVE VIEWER** — 전개 상태에서 왼쪽 세로 패널 상단에 생기던 보라 하이라이트만 제거 (뷰어에서만 적용).
- **OUTRO** — CLEAR THE WAY. / SAVE THE MOMENT. 아래에 얇은 보라 수평선 곡선 (SVG). 스크롤에 따라 아래에서 떠오르며 밝아지고 → 좌우로 퍼진 뒤 유지.

## V4 수정 사항 (오류 수정 · 사용성)

- **검은 박스** — 해상도 자동 조절이 프레임을 그린 *뒤에* 캔버스 크기를 바꿔서, 바뀐 직후의 화면이 지워진(검은) 상태로 표시되었고, 프레임 속도가 기준선 근처면 크기 변경이 1.5초마다 반복되었습니다. 이제 크기 변경은 프레임을 그리기 *전에* 하고, 올리는 쪽은 6초 간격·최대 3회로 제한해 반복되지 않습니다.
  - 추가 안전장치: 장면을 그린 직후 NaN/무한대 값을 제거하는 패스(`post.js` Sanitize)를 넣어, 한 픽셀의 계산 오류가 블룸을 타고 큰 검은 사각형으로 번지는 현상을 막았습니다. 바닥 반사(`ground.js`)도 같은 검사를 합니다.
- **스크롤 속도** — 타임라인 1단위당 스크롤 길이 화면 높이의 19% → 32%(모바일 22% → 30%), scrub 1.15 → 1.6.
  마우스 휠은 한 번에 최대 화면 0.6배까지만 목표를 옮기고, 페이지는 초당 화면 1.6배 이하 속도로 부드럽게 따라갑니다. 휠을 세게 돌려도 여러 장면을 건너뛰지 않습니다. 터치·키보드·스크롤바·챕터 버튼은 원래대로 동작합니다.
- **INSTALLATION** — 내려오는 카메라가 골목 입구에 너무 붙어 모서리 건물의 옆벽이 화면 1/3을 가리던 구간의 카메라 x 값을 4.8 → 3.3으로 조정.

## V5 수정 사항 (연출 · 시각 완성도)

- **SOLUTION 제품 등장 — 보라 라이트 스윕** (`worlds/studio.js`, `main.js`, `timeline.js`의 `SWEEP`)
  - 제품 길이 방향으로 얇은 바이올렛 빛이 약 1초 동안 한 번 지나갑니다. 움직이는 포인트 라이트 2개(실제 스펙큘러 하이라이트) + 셰이더 빛 띠(선명한 코어 + 짧은 잔광, 모서리일수록 밝게).
  - 해당 구간에 들어올 때마다(위·아래 어느 방향이든) 한 번 실행되고, 머무는 동안 반복되지 않습니다. 모델·재질 기본값·카메라는 그대로.
- **PROBLEM 구급차** (`timeline.js`, `people.js`, `ambulance.js`, `ground.js`)
  - 구급차 위치 z -92 → -24, 마지막 카메라를 사람 머리 위 높이(2.4 m)로 낮추고 가깝게(z -7.5) — 전면·경광등이 보이고 화면을 가득 채우지 않음.
  - 구급차 앞·옆에 정체된 인파 48명(일부는 구급차 쪽을 돌아봄)을 별도로 배치, 정체 상태에서만 표시.
  - 경광등 점멸에 맞춰 붉은/푸른 빛이 젖은 바닥에 번지고(점멸 동기화), 경광등 조명 범위를 넓혀 사람·벽에도 닿게 함. 사이렌은 거리가 보이는 순간부터 켜짐.
- **명동 간판** (`worlds/city.js`)
  - 건물 간판의 글자 제거. 크기·위치는 그대로이고(난수 사용 순서를 유지해 도시 배치가 바뀌지 않음), 어두운 유리 하우징 + 안에서 빛나는 아크릴 확산면 + 흰 코어의 네온 튜브 테두리 + 미세 라인 + 유리 반사로 표현. 색은 바이올렛·핫핑크·사이언·마젠타·쿨화이트.
  - 창문 글자 → 발광 필름 띠, LED 미디어 파사드 글자 → 추상 빛 도형, 상점 유리 포스터 글자 → 빛나는 포스터 면.
  - 포장마차 메뉴판은 건물 간판이 아니라서 그대로 두었습니다.
- **바닥 반사** (`ground.js`) — 실제 반사 비중을 높이고, 반사가 밝은 곳에서만 반짝이는 물기 글린트 추가. 바닥에 그린 가장자리 네온선은 약하게.
- **화이트 홀로그램 2개** (`worlds/cityCyber.js`) — 글자 없는 추상 빛 조형(흐르는 등고선 링·코어·필라멘트·코너 프레임), 쿨화이트/실버블루, 아주 느린 밝기 변화. 벽판·지지 암·프로젝터 레일로 건물에 고정되어 거리 쪽으로 돌출. 카메라 가까이에서는 자동으로 사라짐.
- **보름달** — 거리 끝 하늘에 은은한 보름달(헤일로 포함). 거리 끝 원경 빌딩 높이를 낮춰 살짝 보이게 했습니다.
